# 多端同步：扫码配对 + 局域网直传

选型理由见 [ADR 0004](../decisions/0004-sync-qr-lan.md)。代码位置：界面在 `app/lib/features/sync/`，逻辑在 `backend/lib/src/sync/`。

## 用户流程

1. 设备 A 打开「同步」，屏幕上显示二维码。
2. 设备 B 打开「同步」，扫描这个二维码。
3. 两台设备直接建立加密连接，交换各自缺少的变更，完成后两边数据一致。

没有共同的 Wi-Fi 时，让其中一台手机开热点，另一台连上，流程完全一样。

## 二维码内容

- A 的局域网 IP 和监听端口
- 一次性配对密钥（只对本次会话有效，过期作废）
- A 的 device_id 和协议版本

## 会话协议（草案）

1. B 连接 A，用二维码里的一次性密钥完成握手，建立加密通道。具体的加密方案在实现时选定，届时补充 ADR。
2. 双方交换「我已经拥有的、来自各设备的最大 HLC」（相当于版本向量）。
3. 各自发送对方缺少的变更日志条目，分批传输并压缩。
4. 各自在后台 isolate 里合并收到的变更，并回复确认。
5. 会话结束，A 关闭监听端口。

## 数据模型

- 每张业务表的公共字段：`id`（UUIDv7）、`hlc`、`device_id`、`deleted`。
- 变更日志表：追加写入，记录 `(seq, table, row_id, hlc, device_id, payload)`。本地每次写入时，在同一个事务里同时写业务表和变更日志表。
- **合并规则**：按行做 LWW（last-writer-wins，最后写入者胜出）。HLC 大的一方胜出；HLC 相同时比较 `device_id`，保证每台设备算出的结果都一样。
- 删除只打标记（tombstone），这样删除操作也能同步到其他设备。
- 记账数据大多只追加，真正的冲突很少。

## 权限与平台

| 平台 | 需要的权限 |
|---|---|
| Android | 相机（扫码）、网络 |
| iOS | 相机（扫码）、本地网络（Info.plist 中填写 `NSLocalNetworkUsageDescription`） |

## 限制与异常处理

- 部分公共 Wi-Fi 开启了设备隔离，设备之间连不上：提示用户改用热点。
- 传输中断：已经确认的批次保留，下次同步从断点继续（变更日志是幂等的）。
- 两台设备的协议版本不一致：拒绝同步，并提示升级。
