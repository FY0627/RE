# iOS Swift 版：银行卡资金变动自动记账

选型见 [ADR 0008](../decisions/0008-ios-swift-shortcuts-app-intent.md)。代码：
`ios-swift/Bookkeeping/Intents/`（App Intent）→ `ios-swift/Packages/BKCore/Sources/BKBackend/`（解析与入账）→ `BKDatabase`（SQLite）。

## 闭环

```
资产页添加银行卡（银行、后四位、卡类型、币种或多币种，选填初始余额）
  → 「设置自动记账」→ 跳转快捷指令，用户新建一个「信息」自动化（信息包含「银行」，立即运行），所有卡共用；邮件自动化可选
  → 银行短信 / 邮件到达 → 系统运行自动化 → 后台调用 App Intent「记录银行动账通知」（不打开 App）
  → BKBackend：归一化 → 分类 → 解析 → 匹配账户 → 去重 → 同一事务入账 / 写待处理
  → 用户下次打开 App 时首页、卡片详情、统计刷新
```

## 输入协议（App Intent 参数）

| 参数 | 必填 | 说明 |
|---|---|---|
| 通知内容 | 否（缺失记为「空输入」日志） | 自动化里选「快捷指令输入」或其「内容」 |
| 来源 | 默认短信 | 短信 / 邮件 / 其他文本 |
| 发件人、主题、接收时间、消息标识 | 否 | 只有系统实际提供时才填；App 不用处理时间冒充接收时间，不编造消息 ID |
| 绑定账户 | 否 | `AccountEntity`；同尾号多卡时辅助匹配，正文尾号优先 |

返回值：一句处理摘要（例如「入账 1 笔」「待处理 1 条」），不弹任何对话框。

## 分类：哪些会记成交易

| 类别 | 处理 |
|---|---|
| 已发生的资金变动 | 入账（`status = posted`） |
| 支付失败 | 保留记录，`status = failed`，不计入收支和余额推算 |
| 预授权、冻结 | `status = hold`，不冒充已结算消费；预授权完成为 `posted`；撤销/解冻为 `holdReleased` |
| 验证码 | 只记日志，**不保存正文** |
| 营销、还款/账单/扣款提醒（含「将于…扣款」） | 只记日志 |
| 电子账单、对账单 | 只记日志，不把历史明细再入账一遍 |
| 只有余额 | 保存为银行通知余额快照，**不凭余额差额编造交易** |
| 信用额度变化 | 只记日志，不是资金或负债变化 |
| 无法识别 | 进入待处理，不丢弃 |

## 交易性质（不是用户分类）

消费、入账、工资、转入、转出、退款、还款、扣息、手续费、存入、取款、利息、冲正/撤销、其他（方向明确但性质不明）。
方向（流入 / 流出）相对账户本身：信用卡消费为流出、还款为流入。只写「还款」不写方向时，按账户卡类型决定。

## 解析规则要点

- **归一化**：HTML 转文本（`<blockquote>` 标为引用）、实体解码、全角转半角、去零宽字符。
- **邮件历史**：去掉 `>` 引用行和「Original Message / 原始邮件 / 写道」之后的内容；转发邮件取转发正文。
- **金额角色**：数字前最近的标签决定含义——余额、可用额度、手续费、累计、应还/最低还款、积分，其余为交易金额。
  同一句出现两个交易金额（例如「消费 100 实际扣款 95」）视为歧义，进入待处理。
- **手续费**：「含手续费 X」→ 本金 = 总额 − X，另记一笔手续费；「转出 1000，手续费 2」→ 两笔，均不重复计算。
- **金额格式**：`1,234.56`、`1.234,56`、`12,50`、`1'234.50`；三位一组对两位小数币种是千位分隔；
  KWD 等三位小数币种的 `1.234` 视为歧义。全部转为最小货币单位整数。
- **币种**：以通知里写明的为准（人民币/元/¥/EUR/€/USD/HK$…）；`¥` 在中文通知里优先 CNY 但保留 JPY 候选；
  通知没写币种、或只写了「元」时使用账户主币种；写了 `¥`、`$` 等多义写法时优先取账户持有的币种（多币种账户据此区分）。
  **不根据手机地区推断**。都无法确定时进入待处理。
- **时间**：交易时间按通知原文保存为「墙上时间」（不做时区换算），只写月日时按接收时间推断年份并标记；
  `03/04` 这类无法区分日月的日期不写日期。交易时间与系统接收时间、App 处理时间分开保存。
- **尾号**：尾号/末四位/卡号**1234/账户1234/card ending 1234 等写法；「向尾号 XXXX 转账」中的是对方账户。
- **交易对方**：商户/对方户名/在…消费/…向您转账/at MERCHANT 等写法；缺失为空，不编造。摘要字段只在不是通用词（消费、转账、工资…）时作为对方。

### 支持范围与样例依据

`Tests/BKBackendTests/ParserSampleTests.swift` 中的样例均为**按公开常见写法构造的脱敏文本**，覆盖：
招商、工商、中国银行等中文短信常见句式，英文银行卡短信 / 邮件，HTML 邮件、回复历史、转发、多笔交易邮件。
尚未用每家银行的真实通知逐一验证。识别不了的格式进入待处理；新增格式时在 `Lexicon.swift` 补词并补样例测试。

## 账户匹配

1. 正文尾号与账户后四位相同；
2. 同尾号多张卡时，用短信号码 / 邮件域名 / 正文【签名】识别的银行过滤；
3. 仍有多张时，若快捷指令绑定了其中一张，用它；否则进入待处理（`多个账户都可能匹配`），由用户在候选中确认；
4. 正文没有尾号：只有绑定账户时进入待处理（`通知里没有卡号尾号`），不直接入账；
5. 没有任何匹配账户：进入待处理；之后添加了该尾号的账户会自动重新匹配。

## 去重与事务

| 层级 | 规则 |
|---|---|
| 输入 | 指纹 = 来源 + （消息标识 或 归一化正文）+ 发件人 + 主题 + 系统接收时间。重复执行、并发多个自动化命中同一条通知 → 只处理一次（`UNIQUE` 约束） |
| 交易 | 有交易流水号/参考号 → 按账户 + 流水号；否则通知时间精确到分钟 → 按账户、方向、金额、币种、性质、状态、时间、余额 |
| 跨来源 | 短信与邮件特征完全一致 → 合并为同一笔的两份来源证据；只是金额相同、时间接近 → 待处理（`可能与已有流水重复`），由用户判断 |
| 同来源同特征 | 不会静默合并：进入待处理，可确认为另一笔真实交易 |

整个处理（指纹、记录、余额、待处理、转账关联）在一个 `BEGIN IMMEDIATE` 事务里，失败整体回滚。
**不会仅凭同金额、同商户、时间接近就删除第二笔交易**；所有合并都保留来源证据。

## 内部转账、还款、退款

- 自己两张卡互转：两边流水都保留；金额相同、方向相反、30 分钟内且唯一匹配（或正文写明对方尾号是自己的卡）→ 同一转账组，不计入收支。
- 信用卡还款：借记卡付出与信用卡收到都记为「还款」，不计入支出/收入；能配对时同组。信用卡上原有的消费才是支出。
- 退款 / 冲正：新记一笔流入，能唯一找到原交易时建立关联；原交易不覆盖、不删除。

## 余额

- **银行通知余额**：通知中写明的余额，按通知内时间（而不是到达顺序）取最新，迟到的旧通知不会覆盖新余额。
- **初始余额**：用户在添加卡或卡片详情里填写的「现在」的余额（可填欠款，即负数），和银行通知余额分开保存、分开显示。
- **推算余额**：从「最新银行通知余额」和「初始余额」中较晚的一个出发，加上之后已入账的流水；两者都没有时显示「未知」。
  多币种账户每个币种分别推算（各自的银行通知余额、初始余额和流水），不做换算。
  银行通知余额之间按通知内时间比较；和初始余额比较时用通知到达手机的时间（通知内时间是银行所在地时间，和手机时区可能不同）。
- 信用卡通知中的「余额」含义因银行而异，不计入净资产；只有用户给信用卡填写了初始余额时才按推算余额计入。

## 自动化状态（只展示可观测事实）

| 状态 | 含义 |
|---|---|
| 已提供 App 动作 | 随 App 安装，快捷指令可搜索 |
| 已导入快捷指令 / 已启用触发器 | iOS 不提供查询接口，App 无法得知，界面明确写「无法读取」 |
| 已验证 | 这张卡至少有一次真实输入成功处理，显示最近接收时间、来源和累计次数 |

## 记账结果通知

- 「我的 › 自动记账 › 记账结果通知」：全部 / 仅失败 / 关闭（默认关闭，第一次打开时请求通知权限）。
- 每笔交易一条本机通知（UserNotifications，不经过服务器）：
  - 成功：「尾号 1234 卡，消费，¥128.00，记账成功」；
  - 失败：「尾号 1234 卡，消费，128.00，记账失败：没有与尾号匹配的账户，已放入待处理」；
  - 整条无法识别：「收到一条无法识别的银行通知，已放入待处理」。
- 不发通知：同一笔交易的另一来源合并、重复输入、验证码、营销信息、只有余额的通知。通知不出声（银行短信本身已经响过）。
- 金额和尾号会显示在锁屏上；不想显示时在系统设置里把「显示预览」改成「解锁时」。
- 入账结果里的每一笔见 `IngestResult.items`（`BKModel/Ingest.swift`），通知文案在 `App/IngestNotifier.swift`。

## 隐私与数据保留

- 不联网（汇率由快捷指令导入，见 [ADR 0011](../decisions/0011-ios-swift-multi-currency-and-rates.md)）；日志只记录结果类别和计数，不记录正文、金额、发件人。
- 原始正文默认保留 30 天（可选 7 / 30 / 90），到期清空正文、保留指纹与流水；待处理项的正文保留到处理完成。验证码正文从不保存。
- 数据库文件保护等级 `completeUntilFirstUserAuthentication`：首次解锁后锁屏可后台写入；开机后从未解锁时入账失败并由快捷指令显示错误。

## 限制

- 只能处理系统实际交给 App 的内容；系统未投递、未触发的通知无法补回，不能保证银行发送了每一笔。
- 邮件自动化依赖 iPhone 自带「邮件」App 收到邮件；只能按发件人、主题等筛选。
- 自动化必须由用户在快捷指令里手动创建；App 无法创建、导入或查询。按关键词「银行」触发时，普通短信也会触发：没有金额也没有尾号的记为「不是动账通知」，只留在接收日志里。
- 免费签名约 7 天到期，到期期间自动化失败。
