# 0005 自动记账：截图 + OCR

- 状态：已采纳
- 日期：2026-10-20

## 背景

用户在微信、支付宝、银行 App 里付款后，希望不用手动输入就能记账。iOS 可以用快捷指令；Android 上有多种做法，需要选一种。

## 备选方案（Android）

| 方案 | 优点 | 缺点 |
|---|---|---|
| **悬浮窗 + 截屏 + 本地 OCR** | 两端体验一致；不需要无障碍这类敏感权限；对方 App 改版的影响小；只在用户点击时才运行，低端机负担小 | 需要用户点一下；首次要授权一次屏幕录制 |
| 无障碍服务读取页面 | 全自动、覆盖面广 | 权限敏感；微信改版就会失效；容易被系统杀后台 |
| 通知监听 | 资源占用极低 | 微信 / 支付宝不是每笔都有通知，覆盖面不全 |
| 读取短信 | 银行卡交易准确 | 只覆盖银行卡；属于敏感权限 |
| Xposed / Shizuku | 能力最强 | 门槛太高，不符合低成本目标 |

iOS 不允许悬浮窗，也拿不到其他 App 的页面内容，用快捷指令是唯一可行的方案。

## 决定

两端统一采用 **截图 → OCR → 文本 → 后端解析 → 记账**：

- **Android**：点击悬浮窗触发截屏，在本地做 OCR，然后记账。
- **iOS**：快捷指令完成截图和 OCR（使用系统的「从图像中提取文本」），再通过 App Intent 把文本交给 App 记账。

细节见 [features/auto-bookkeeping.md](../features/auto-bookkeeping.md)。

## 影响

- `native/` 负责采集，只输出 OCR 文本；`backend/lib/src/auto_entry/` 负责解析，两端共用同一套解析代码。
- Android 端的 OCR 先用 ML Kit 中文识别（模型打包进 App），封装成接口，以后可以替换为 PaddleOCR。
- 以后可以把通知监听作为补充采集方式，届时新增一份 ADR。
