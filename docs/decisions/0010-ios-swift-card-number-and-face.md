# 0010 iOS Swift 版：选填完整卡号，卡面支持自定义图片与文字样式

- 状态：已采纳（`ios-swift/`）
- 日期：2026-10-25

## 背景

最初账户只保存后四位，不保存完整卡号。真机试用后用户希望在卡片详情里查看卡号，并能自己换卡面图片、改卡面文字的颜色和大小。
目标设备包括低端机，卡包滚动和详情转场不能因为图片掉帧。

## 决定

**卡号**

- `accounts` 新增 `card_number`（迁移 3），**选填**，在「卡片详情 › 卡片信息」里填写。
- 只接受 12–19 位数字，末四位必须与 `last4` 一致（`LedgerBackend.updateCardInfo` 校验）。
- 自动记账仍然只用后四位匹配，完整卡号不参与解析、匹配和日志。
- 只保存在本机 SQLite（文件保护 `completeUntilFirstUserAuthentication`，与账本一致），界面默认遮住，点按显示。

**卡面**

- `accounts` 新增 `face_image_id`、`face_text_color`、`face_text_scale`（迁移 3）。数据库只存图片标识，图片本身是文件。
- 用系统 `PhotosPicker` 选图（不需要相册权限，不引入第三方依赖）。
- 选图时用 ImageIO 生成缩略图（不解码原图全尺寸），按卡片比例居中裁剪、缩小到卡片的屏幕像素（最大 1200px 宽），
  存成 JPEG 到 `Application Support/Ledger/CardFaces/<标识>.jpg`。
- 显示时后台解码、`preparingForDisplay()`，按标识缓存在内存（`CardFaceImages`）；卡包滚动和转场只绘制已解码的位图。
- 每次换图生成新标识；换图、移除、取消编辑时删除不再使用的文件。
- 文字样式只有一个颜色和一个大小倍数（0.8–1.3），对卡面上所有文字生效。
- 用图片时卡面上只保留右上角的金额，其他文字和图标都不画（默认白字）；配色只在没有图片时才能选。

## 取舍

- 选填卡号改变了「只保存后四位」的约定，但数据不离开设备，且不填时行为与之前完全相同。
- 不做图片裁剪编辑器：居中裁剪覆盖大多数照片，减少界面和代码。
- 每张卡单独设置文字颜色、大小，不分别设置每一行文字，避免编辑界面过于复杂。
