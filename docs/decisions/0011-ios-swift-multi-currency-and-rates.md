# 0011 iOS Swift 版：多币种账户，主要币种与可选的联网汇率

- 状态：已采纳（`ios-swift/`）
- 日期：2026-10-25

## 背景

- 有的银行卡本身就是多币种账户（例如恒生万事达扣账卡），一张卡里同时存港币、美元、人民币。
  原来的账户只有一个币种，这类卡的流水和余额没法正确归类。
- 用户有多个币种的卡时，净资产不能简单相加。原来只显示一个币种，其他币种看不到。
- 项目原则是本地优先、不联网（[ADR 0001](0001-local-first-no-server.md)）。按汇率换算净资产需要汇率数据。

## 决定

**多币种账户**

- 账户保留一个**主币种**（`accounts.currency`），新增 `extra_currencies`（逗号分隔的其他币种）。单币种账户为空。
- 初始余额改为按币种保存：新表 `opening_balances (account_id, currency, amount_minor, set_at)`。
  迁移 4 把原来的初始余额迁入新表（记为主币种），`accounts.opening_balance_*` 两列不再使用。
- 余额按「卡 × 币种」分别推算：每个币种取该币种最新的银行通知余额或初始余额作起点，加上之后同币种的流水。
  收到过账户未声明的币种的银行余额时，这个币种也单独列出。
- 入账时的币种：通知没写、或只写了「元」这类含糊写法时记为主币种；否则优先取账户持有的币种
  （多币种账户里 `¥`、`$` 等写法据此区分）；账户不持有任何候选币种时沿用原来的规则。
- 卡面始终显示原币种（多币种卡显示主币种余额和「HKD +2」这样的标记），不做换算。

**主要币种与汇率**

- 「我的 › 币种与汇率」里选择**主要币种**，保存在本机设置。
- **联网获取汇率默认关闭**，由用户打开。打开后，App 启动或回到前台时、距上次下载超过 6 小时才请求一次
  `https://open.er-api.com/v6/latest/USD`（ExchangeRate-API 的免密钥公开接口，每日更新，覆盖 160 多个币种）。
  请求只含基准币种代码，使用无缓存、无 Cookie 的临时会话，不上传任何账本数据。最近一次结果缓存在本机。
- 汇率只用于资产页净资产的换算显示：各币种的资产、负债分别换算成主要币种后相加，缺汇率的币种不计入并标出。
  账本、卡片、流水、统计始终是原币种整数金额。
- 关闭联网时不使用旧缓存；净资产显示主要币种的金额，其他币种分开列出。

## 备选方案

| 方案 | 结论 |
|---|---|
| 用户手动填汇率 | 维护负担大，容易过期 |
| Frankfurter（欧洲央行数据） | 免密钥，但不含澳门元、新台币等币种 |
| 需要 API Key 的商业汇率接口 | 要在 App 里放密钥，或者需要自己的服务器转发，违背「没有服务器」 |
| **ExchangeRate-API 免密钥接口，用户自愿开启** | 采纳。数据源不可用时只影响换算显示，不影响记账 |

## 影响

- App 第一次联网时，系统可能询问是否允许使用无线数据；拒绝时汇率获取失败，其余功能不受影响。
- 自动记账的 App Intent 仍然不联网。
