# 0003 本地数据库使用 SQLite + drift

- 状态：已采纳
- 日期：2026-10-20

## 背景

需要一个性能开销小、性能高、稳定的本地数据库。账本需要做汇总、分组统计和关联查询，并且要支持多端同步合并。

## 备选方案

| 方案 | 性能 / 开销 | 查询能力 | 稳定性 / 维护 | 结论 |
|---|---|---|---|---|
| **SQLite + drift** | 通过 FFI 直接调用 SQLite C 库，不经过平台通道；支持后台 isolate 和 WAL | 完整 SQL，SUM / GROUP BY 等统计在 C 层完成 | SQLite 是最稳定的嵌入式数据库之一；drift 成熟、持续维护；代码生成只发生在开发期 | ✅ 采纳 |
| sqflite | 每次查询都经过 MethodChannel 序列化，大量小查询时明显更慢 | 完整 SQL | 成熟稳定 | SQL 和迁移要手写，而且更慢 |
| sqlite3（裸 FFI） | 最快、最薄 | 完整 SQL | 稳定（drift 就是基于它） | 可以用，但 SQL、迁移、类型映射都要手写 |
| Isar | 读写很快 | 对象查询，聚合能力弱 | 原作者已停止维护，只剩社区分支 | ❌ 长期风险高 |
| Hive / Hive CE | 纯 Dart；box 会整体载入内存，数据越多占用越大 | 只能键值读写，没有查询 | 社区分支在维护 | ❌ 不适合账本和统计 |
| ObjectBox | 很快 | 对象查询，聚合有限 | 核心库不开源，同步功能收费 | ❌ 和开源目标冲突 |
| Realm | — | — | MongoDB 已于 2024 年弃用 SDK | ❌ |

## 决定

采用 **SQLite + drift**。

## 影响

- `database/` 将依赖 `drift`（以及提供 SQLite 原生库的配套包），开发期依赖 `drift_dev` + `build_runner`。具体版本在编写表结构时确定。
- 数据库连接运行在后台 isolate；统计查询用 SQL 聚合，列表查询分页。
- 每张业务表都包含同步所需的公共字段（见 [overview.md](../architecture/overview.md#数据模型的共同约定)）。
- 表结构的每次修改都要附带迁移和迁移测试。
