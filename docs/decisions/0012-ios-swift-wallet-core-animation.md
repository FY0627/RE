# 0012 iOS Swift 版：卡包与详情转场改用 UIKit + Core Animation

- 状态：已采纳（`ios-swift/`）
- 日期：2026-10-27

## 背景

- 资产页点按银行卡展开详情的转场原来用 SwiftUI 实现，前后改了十几轮（只用渲染变换、卡包和详情各画一份卡片再交接、
  等第一页流水读到再升起内容等），真机上仍然掉帧明显，达不到 Apple 钱包的流畅度。
- 原因在结构上：SwiftUI 的动画由 App 主线程逐帧计算。点按后的 0.5 秒里主线程同时要新建详情页（新的滚动区和卡片副本）、
  读第一页流水并生成流水行、计算待处理数量后整页重新计算、因标签栏显隐整个 TabView 重新计算。
  120Hz 屏幕每帧约 8 毫秒，其中任何一件事占用十几毫秒，动画就停顿几帧。
- Apple 钱包用 Core Animation：动画提交后由系统渲染进程播放，App 主线程忙不忙都不影响。

## 决定

- 卡包、详情列表和两者之间的转场改用 UIKit（`UI/Assets/WalletController.swift`、`WalletDetailList.swift`），
  动画用 Core Animation（`CardMotion.swift`）。界面外观、交互和动画参数保持不变（弹簧 response 0.5、阻尼 0.86 等）。
- 卡面（`WalletCardView`）、标题区和净资产卡、详情的余额区和每一行流水仍由 SwiftUI 画，
  分别放在 `UIHostingController` 和 `UIHostingConfiguration` 里。顶部按钮（液态玻璃）、标签栏和所有弹出页面仍是 SwiftUI。
- 每张卡只有一个视图，放在卡包和详情两个滚动区的上层，按滚动距离摆放；打开 / 关闭时把模型位置改成终点，
  再加叠加（additive）动画。动画途中滚动或再次点按，新的位移叠加上去，从当前位置平滑转向。
- 卡片不接收触摸：点按由下面的滚动区识别，再按卡片显示的位置找到点中的卡；拖动卡片就是拖动下面的滚动区。
- 详情列表用 `UICollectionView`（行复用，只生成看得到的行）。第一页流水、笔数、待处理数量读到后，
  余额和流水整块从屏幕底下升起（只动显示位置，升起途中也能滚动、点按）。
- 标签栏显隐的修饰符从根视图移到资产页，打开详情时其他标签页不重新计算。

## 备选方案

| 方案 | 结论 |
|---|---|
| 继续在 SwiftUI 里减少动画期间的主线程工作（先读好流水、挪走标签栏修饰符等） | 能缓解，但动画仍由主线程逐帧计算，任何新的主线程工作都会再次造成掉帧 |
| 转场时用卡片截图在 UIKit 覆盖层里做动画，结束后换回 SwiftUI | 详情要求点开马上能滑动、动画中途能转向，截图层要一直跟着 SwiftUI 的滚动，容易错位、抖动 |
| **卡包和详情整体改用 UIKit + Core Animation，内容仍由 SwiftUI 画** | 采纳。动画由渲染进程播放，不受主线程影响；与钱包的做法一致 |

## 影响

- 资产页的卡包和详情不再是纯 SwiftUI。改转场或卡片位置看 `WalletController`，改详情列表看 `WalletDetailList`，
  改动画曲线看 `CardMotion`；改卡面、余额区、流水行仍改对应的 SwiftUI 视图。
- 顶部按钮的动画仍由 SwiftUI 驱动：流水行生成的那一瞬间主线程忙时，它可能掉一两帧；卡片和内容的动画不受影响。
- 读屏：卡包里的卡用放在卡包滚动区里的读屏元素代替（聚焦时自动滚到那张卡）；详情顶部的卡片位置代表选中的卡，激活即返回。
- 不引入第三方依赖。
