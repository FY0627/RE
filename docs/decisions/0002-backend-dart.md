# 0002 后端（手机内业务层）使用 Dart

- 状态：已采纳
- 日期：2026-10-20

## 背景

后端运行在手机里，负责业务规则、统计、同步合并和自动记账文本解析。要求是性能好、占用低、稳定，而且要能在 2020 年左右的低端机上运行。

## 备选方案

| 方案 | 性能 | 占用 | 稳定性 / 维护成本 |
|---|---|---|---|
| **Dart** | AOT 编译成 ARM 机器码；和前端在同一进程，调用没有跨语言开销 | 不需要额外的运行时 | 内存安全；前后端同一种语言，共用数据模型，只维护一套代码 |
| Rust（flutter_rust_bridge） | 计算性能最好，没有 GC | 每个 ABI 的安装包增加几 MB | 要多一套交叉编译工具链；每次调用都要跨 FFI 序列化；构建复杂 |
| Kotlin + Swift 各写一份 | 好 | 小 | 同一套逻辑写两遍，两端行为容易不一致 |
| Go（gomobile） | 一般 | 自带运行时和 GC，安装包增加几 MB | cgo 有调用开销，没有明显收益 |

## 决定

使用 **Dart**。记账类负载的重活本来就交给原生库完成：数据库是 SQLite（C），OCR 是 ML Kit / PaddleOCR 这类原生库。业务层本身的计算量不大，用 Dart 就够了。

## 影响

- `backend/` 和 `database/` 是纯 Dart 包，不依赖 Flutter。
- 约束：重计算不能占用 UI isolate（见 [overview.md](../architecture/overview.md#线程模型)）。
- 如果性能分析证明某个计算是热点（例如大量数据的同步合并），可以只针对那一处引入 Rust，届时新增一份 ADR。
