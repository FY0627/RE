# 0014 iOS Swift 版：参考 MOZE 的基础记账——支出 / 收入 / 转帐、自定义分类、手动记一笔、合成一单

- 状态：已采纳（`ios-swift/`），2026-10-28 修订（见文末「修订」）
- 日期：2026-10-28

## 背景

- 自动记账把每条银行通知记成一行：自己两张卡互转、还信用卡各占两行；手续费、退款各占一行；失败、冻结、解冻也在首页。
- 「交易性质」有 14 种（消费、入账、转入、存入、取款、冲正……），看着都差不多；没有分类，只能看到对方名字（常常是「财付通-xxx」），
  看不出钱花在哪。
- 没有手动记一笔：现金、电子钱包、邮件和 App 通知还没接上的消费都记不了。
- 参考 [MOZE 的记账教学](https://doc.moze.app/)，只取它最基础的部分：账户 + 分类 + 支出 / 收入 / 转帐，余额和现实对得上。

## 决定

**识别不动，只改「怎么给你看、怎么算」**：银行通知的识别、去重、识别模板、原始流水都保持原样。

**三种类型**（`EntryType`，由交易性质、方向和转账关联推出来，不保存；SQL 里是 `RecordDAO.entryTypeSQL`，两边规则一致）

| 类型 | 包括 |
|---|---|
| 转帐（不算收支） | 自己的账户之间互转（配对的，或确认对方是自己）、还款、存取现金 |
| 支出 | 其余流出；退款和流入的冲正也算支出（从支出里减掉，不算收入） |
| 收入 | 其余流入 |

没确认对方的转账先按转给别人算（转出是支出、转入是收入），和原来一样。存取现金原来算支出 / 收入，现在算转帐。

**分类**（迁移 8：`categories`、`records.category_id`）

- 最多两层：大类和小类。支出、收入默认一套（收入默认只有一层），只是第一次打开时写进数据库的起点，用户可以增加、删除、改名、换图标、排序、隐藏，
  小类可以挪到别的大类下面，两个分类可以合并。删除时选原来的记录改记到哪，不选就回到待分类，**记录不删**。
- 手续费、扣息是系统分类，转帐有三个分类（转帐、还信用卡、存取现金），自动记账要用：不能删，可以改名、换图标。
  转帐的分类按交易性质对应，不保存在流水上。
- 自动归类（`BKBackend/Categorizer.swift`，入账时在同一个事务里）：手续费、扣息、工资、利息直接归类；退款跟着原交易的分类；
  其余按交易对方记住的分类（`counterparty_rules`，键是「类型|对方」）。用户给一个对方选过一次分类，以后这个对方的都自动归类，
  同一个对方还没分类的也一起归类。只写了「财付通」「支付宝」「银联」这类支付渠道、看不出商户的不记（`CounterpartyKey`）。
  记住的是饮食或某一餐时，按交易时间猜早餐（5–10 点）、午餐（10–15 点）、晚餐（17–22 点）。
- 没确认对方的转账：选了分类就是转给别人；选「转给自己」就算转帐，并记住这个对方（`own|对方`），以后这个对方的转账自动算转帐。
- 剩下的是「待分类」：首页顶上提示「N 笔待分类」，点进去一笔点一下分类，可以顺手写备注。原来的「转账待确认」并进这里。

**首页一笔钱只占一行**（`RecordFilter.feed` / `mergeFees`）

- 只列已入账的；失败、冻结、解冻只在卡片详情里看。
- 配对的转帐只留转出那边，写成「招行 → 工行」；同一条通知拆出的手续费合到那一笔下面（「手续费 ¥2」）；退款仍单独一行，原交易下面写「已退 ¥x」。
- 标题按「备注 → 交易对方 → 分类名」，图标是分类图标；方向、交易性质、状态、来源、原始通知收进详情的「更多信息」。
- 筛选：全部 / 支出 / 收入 / 转帐。

**手动记一笔**

- 首页右上角「+」：金额 → 分类 → 备注 → 账户（默认上次用的）→ 保存。转帐选从哪到哪，转进信用卡算还款。
- 账户可以是现金、电子钱包（`CardType.cash` / `.wallet`）：没有卡号，表里的尾号填占位 `0000`，**不参与任何匹配**（尾号、账号、快捷指令绑定）。
  不重建 `accounts` 表去掉尾号的约束：重建要在迁移事务里改外键，风险比占位大。
- 手动记的一笔也有一条输入记录（`source = manual`，不写正文，不进接收日志），流水的来源、去重键照常。
- 先手动记、后来同一张卡的银行通知到了（同金额、前后 3 小时）：不再记一次，进待处理问是不是同一笔；手动记之前也先查一下有没有已经记过的。

**一单用了几张卡：合成一单**（`records.order_group`）

- 每张卡各记各的（余额、支出都对），只是显示成一单：首页一行写整单金额和「招商银行 ¥700 + 中国银行 ¥300」，分类统一成一个。
- 在流水详情里手动选同一单的其他几笔，可以拆开；不自动合并（不同银行写的商户名常常不一样，同一时间在同一家买两次也正常），
  别的卡、10 分钟以内的只标「可能是同一单」。

**统计**：本月支出（减去退款）、收入、结余，再按分类排（点进去看小类和每一笔），最后按账户。转帐单独列一行，不算收支。

**校准余额**：就是原来的初始余额（MOZE 的余额调整），只在「卡片信息 › 编辑」里改名，不加显眼的入口。

## 不做

专案、预算、借还款、分期、周期记账、标签、商家、一笔拆成几个分类、拍照。

## 影响

- 迁移 8 只新增表和列、补默认分类，不改已有数据；能直接归类的旧流水（手续费、扣息、工资、利息）补上分类，其余是待分类。
- 统计口径变化：存取现金不再算支出 / 收入；首页「本月支出」改成减去退款后的金额。

## 修订（2026-10-28，真机试用后）

- **不猜分类**：先把识别准确、记账可靠做好。去掉「按交易对方记住分类」「按时间猜三餐」「记住对方是自己的账户」；
  自动归类只剩通知写明了的（手续费、扣息、工资、利息）和退款跟着原交易。迁移 8 建的 `counterparty_rules` 表不再读写，留着不删
  （删表要新迁移，没有好处）。待分类里点一笔打开面板，选好分类点「确定」才保存，可以先换。
- **电子钱包自动记账**：支付宝、微信支付发来的、没写银行卡号的通知记到那个钱包的账户；同一个钱包有几个账户时让用户选
  （`WalletDirectory`，见 `docs/features/ios-swift-auto-bookkeeping.md`「电子钱包」）。钱包账户的 `bank_id` 存钱包标识，
  旧账户按名称猜。写了卡号尾号的照常记到卡上。
- **首页本月合计换算成主要币种**：所有币种的支出、收入换算成「我的」里选的主要币种合计（外币交易有实际扣款用实际扣款，
  否则按交易当天的汇率，和外币扣款同一套 `ChargeCalculator`）；没有汇率的不计入、单独写出来。统计页仍按币种分开。
- **编辑转帐可以选另一边的账户**：那个账户前后 3 天里有对得上、还没配对的一笔就配成一对，没有就在那边补记一笔（来源是手动）；
  手动补记的另一边跟着这一笔改金额、币种和时间，不再是一对时删掉；银行通知记的另一边只解除配对，不删。

## 修订（2026-10-29）

- **先选币种再选账户**：记一笔、编辑流水的币种可以选任何一种（记一笔默认主要币种），不再跟着账户限制。
  账户没有这个币种时按账户的主币种扣款（入账），和自动记账的外币消费同一套：不填实际金额就按交易当天的汇率估算
  （`ChargeCalculator`，填写时提示大概多少），填了就存在 `settlement`。转帐两边各自算：`ManualEntry` 的
  `settlementMinor` 是转出（或支出、收入）的账户，`toSettlementMinor` 是转入的账户。
  原因：先选账户时币种被账户卡住，要先换账户才能换币种；而银行本来就会按主币种结汇，按主币种记是对的。
- **统计按时间段看**：和卡片详情一样在右上角的时间段胶囊里选（全部、本周、本月、上月、今年、自定义），不再左右翻月份
  （`LedgerBackend.stats(from:to:)`，按月的 `monthStats` 留给首页）。下面用分段控件选「按币种」或「按账户」，记住上次选的。
- **统计先看总览**：统计页先是这段时间的支出、收入、结余，所有币种换算成主要币种（和首页的本月合计同一套换算，
  `stats(from:to:convertTo:)`），下面紧接着是按币种或按账户的分段控件和原来的内容（不另开详情页）。默认看本周，本月的首页上有。
  原因：多个币种时一进来就是几块分开的金额，看不出这段时间一共花了多少。
- **搜索金额是模糊的**：只写整数的金额找上下 10%（至少 1）以内的，也找按主币种的实际扣款；写了小数的按原样找。
  原因：用户常常只记得大概多少。
- **流水详情里分类只显示**，改分类在「编辑」里；去掉 `CategoryPickerSheet`。

## 修订（2026-10-30）

- **删除账户保留流水**：停用的账户删除时只做标记（迁移 9：`accounts.deleted_at`，`AccountDAO.markDeleted`），
  不再连流水一起删。删除的账户不出现在资产页、账户列表、净资产、自动记账和统计的账户菜单里；它的流水照常出现在首页、搜索、统计合计里，
  账户名称后面写「（已删除）」（`AccountLabel.deleted`），转帐两边照样配对。编辑这种流水时原来的账户还能选（`LedgerStore.account(id:)` 也找删除的）。
  原因：删卡是不再用这张卡，过去花的钱还是花了，统计和历史不能跟着少。

## 修订（2026-10-31）

- **转帐填到账多少**：转帐的两条流水各记各的金额和币种（`ManualEntry.toAmountMinor` / `toCurrency`，编辑时 `RecordEdit.peerAmountMinor` / `peerCurrency`），
  不再要求一样，也不需要新表：余额本来就按每条流水的账户和币种推算。去掉 `toSettlementMinor`：到账的币种从转入账户持有的币种里选，不再有「按主币种入账」。
  界面在 `UI/Common/TransferSideFields.swift`：币种相同时空着就是一样多，币种不同必须填，提示按汇率大概多少。
- **同一个账户可以转帐**：多币种账户的两个币种之间换汇，只有币种不同才行；信用卡自己换汇不算还款。
- **差额不算支出**：到账比转出少的部分（手续费、汇损）只体现在余额上，不进统计。
  原因：转帐不算收支；换汇时没有可靠的基准汇率，算不出准确的汇损。同一币种的差额在流水详情里写成手续费。
- **配对可以金额不同**：编辑时填了到账多少，银行通知记的另一边也改金额并保持配对；没填时和原来一样，改了金额就解除配对。
  选另一边的账户时按到账金额找对得上的一笔，所以金额差一笔手续费的两条银行通知也能配成一对。自动配对不变，仍要求金额相同。
- **拆开时选拆哪几笔**：`splitOrder(recordIDs:)`，其余的还是一单，只剩一笔时不再是合单。
