# 0001 本地优先，不使用服务器

- 状态：已采纳
- 日期：2026-10-20

## 背景

目标用户希望以低成本使用这个 App：只用手机就能完成所有操作，不需要搭建环境，也不需要购买服务。他们使用的设备可能比较旧，同时可能跨 Android 和 iOS。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 云端服务器 + 账号体系 | 随时随地同步 | 需要长期的服务器成本和运维；隐私数据要上传；离线不可用或体验差 |
| 用户自建服务器（Docker / NAS） | 数据在自己手里 | 用户要有电脑或 NAS，还要会部署，门槛高 |
| **本地优先 + 设备互传** | 零成本、离线可用、隐私好 | 同步时设备需要在身边；没有云备份 |

## 决定

采用**本地优先**：每台设备上的 SQLite 都是完整的数据副本，设备之间直接传输来同步（方案见 [0004](0004-sync-qr-lan.md)）。

## 影响

- 仍然有前端、后端、数据库三层，只是后端运行在手机内（见 [architecture/overview.md](../architecture/overview.md)）。
- 数据模型从第一天起就要支持多副本合并：UUIDv7、HLC 时间戳、删除标记。
- 备份 / 导出属于另外的功能，以后单独决策。
