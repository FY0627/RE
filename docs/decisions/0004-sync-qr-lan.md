# 0004 多端同步：扫码配对 + 局域网点对点直传

- 状态：已采纳
- 日期：2026-10-20

## 背景

不使用服务器（[0001](0001-local-first-no-server.md)），但要支持多台设备之间同步，包括 Android 和 iOS 之间。操作要简单、成本要低，而且只做一种方案。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| **扫码配对 + 局域网直传** | 只要扫一下；一次会话完成双向增量同步；不需要外网；Android ↔ iOS 互通 | 设备需要在身边；需要同一 Wi-Fi，或者一台手机开热点 |
| 导出文件 → 发送 → 导入 | 最通用，可以远程发送 | 手动操作多；双向同步要来回导两次 |
| 只用二维码传数据（动态码） | 完全不需要网络 | 容量很小，只适合极少量的增量 |
| 跨网络点对点（类似 Keet，WebRTC / Hyperswarm） | 不在身边也能同步 | 需要 NAT 穿透和信令服务，违背「不要服务器」；Hyperswarm 依赖 Bare 运行时，对低端机来说太重 |
| 平台专属（Nearby / Multipeer / AirDrop） | 体验好 | 不能跨系统 |
| WebDAV / 网盘中转 | 可以异步同步 | 依赖第三方账号，冲突处理弱 |

## 决定

采用**扫码配对 + 局域网点对点直传**。设计细节见 [features/sync.md](../features/sync.md)。

## 影响

- 用 `dart:io` socket 实现，代码放在 `backend/lib/src/sync/`，不需要原生代码。
- 需要相机权限（扫码）和 iOS 本地网络权限。
- 二维码生成 / 扫描、加密这几个库在实现时选定，届时补充一份 ADR。
