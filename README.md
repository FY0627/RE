# 日常记账 · Flutter App

Flutter 入口直接显示完整 App，自动适配设备尺寸与系统安全区域。手机边框、预览控制栏、四屏展示和模拟状态栏均已移除；日夜外观可在「我的」中切换。

界面以原手机预览的 327px 内屏为基准，字号、间距和控件一起等比例适配。账户卡片的高度随宽度计算，卡堆、详情和切换动画使用同一套尺寸，保持原预览的长宽比例。

连接手机并开启 USB 调试后，在项目目录运行 `flutter run` 即可启动真机调试；多个设备时先运行 `flutter devices`，再用 `flutter run -d 设备ID` 指定手机。

- Flutter 项目位于 `lib/`，默认单屏体验。导航胶囊、右侧加号、玻璃材质、边缘高光及图标均由 Flutter 实现，页面内容保持原样。日间背景采用最新参考图中的灰白色 `#F2F1F6`，导航呈更亮的白色磨砂胶囊；日夜玻璃底座均为 15% 白色遮罩，日间使用 16px 背景模糊并轻微提亮背景，夜间使用 12px 模糊，避免高不透明度白色掩盖磨砂效果。选中框参考 iOS 的同色系半透明层：日间 8% 中性灰，夜间 16% 亮灰，使其与底座区分；图标与文字使用常规粗细。切换时选中框 560ms 拉长回弹、页面 280ms 滑入滑出、未完成的滑动 300ms 回弹。新滑动在接触屏幕时接管未结束的翻页，从当前画面位置继续移动；选中框保留接管时的位置和拉伸形状，同步跟随拖动。连续同向、反向滑动和导航点击均可接续，松手后立即开始收尾动画；取消手势时恢复原目标，保留竖向列表滚动。运行 `run_web.ps1` 可启动 Flutter Web。
- Flutter 加号采用液滴拉伸动画，最细处位于连接段约 62% 的偏下位置、底部保留小圆滴，拉到顶时底部圆滴半径为 14px。最大上拉距离固定为 App 屏幕高度的 15%，过程中没有文字或变色提示。液滴采用一整块轮廓和同一层磨砂、阴影，圆形与细腰沿切线自然衔接。达到位置后松手，按钮保持在上方，底部小圆保持松手时的大小向上收进按钮，再打开现有记账界面，不回弹；未到达或取消手势时，按钮用 600ms 的衰减弹簧上下弹动后回到原位，拉得越远回弹幅度略有增加，原位附近的弹动限制在 6px 以内。键盘 Enter / 空格和辅助功能仍可打开入口。
- Flutter 资产详情入场持续 800ms：所选卡片从点击位置连续移动到详情位置，同时上方账户卡片随所选卡片移动，间距逐渐收拢至完全重叠在其后方，下方卡片仍向下退出，前 560ms 完成；顶部净资产卡片随所选卡片向上退出。导航和加号在前 192ms 各自向内收起，192–560ms 顶部按钮从中心展开，最后 240ms 下方账户内容从底部上移入场。顶部按钮与底部导航共用中心缩放和淡入动画，圆形按钮保持等比缩放。关闭详情恢复为 620ms 的原有逆序动画：所选卡片回到原位，上方账户卡片逐渐展开至原有间距，下方卡片从下方归位，顶部净资产卡片从上方归位、顶部按钮向中心收缩淡出，底部导航和加号在复位的最后一段同时展开，并保留卡堆的滚动位置。本轮仅导航栏恢复完全不透明的时刻延后一帧，加号按原时刻恢复。页面内容保持原样。卡堆收拢及退出结束后停止绘制并暂停内部动画，仅保留原视口及缓冲区内的有限节点和缓存，返回时复用，不挂载全部账户。
- Flutter 切页保留四个页面和各自的滚动状态，静态内容通过 `RepaintBoundary` 复用绘制层。拖动与翻页每帧直接更新绘制偏移，不重建页面、不重新布局；导航选中框独立重绘，玻璃底座、图标和文字不随位置变化反复构建。动画控制器在组件生命周期内复用，切换轨迹只在点击或松手时设置；画面外的页面跳过绘制并暂停动画。资产详情的交易内容、净资产卡片和顶部按钮也作为静态子树复用。
- Flutter 资产卡堆使用专门的懒加载 Sliver，完整保留账户数量，只挂载视窗及附近缓冲区内的卡片，回收范围外的组件和裁剪图层。每张卡保持原来的完整高度、重叠间隔和绘制顺序；仅裁掉被下一张不透明卡片完全遮住的内部区域，保留抗锯齿边缘、圆角、外侧阴影和末张完整卡面。静态卡面按最近使用顺序缓存，最多保留 32 个组件条目，这不是用户卡片数量限制；插画与渐变内容复用绘制子树。卡片坐标由 Sliver 布局计算，不再给所有卡片保留 GlobalKey。详情切换独立移动选中卡片，其余卡片只按原视窗绘制和退出，返回后保留滚动位置。

**仅延后导航栏透明度终点（当前对照）**

已经撤回“卡片复位后再展开底部控件”的改动，恢复之前的 620ms 返回动画、同一进度驱动导航和加号的方式，并移除额外的 180ms 动画控制器。本轮只让导航胶囊第一次达到 alpha 255 的帧保持 alpha 254（透明度 254/255），下一帧恢复为 1；加号完全不延后。两者的缩放、开始出现的时刻、卡片轨迹和清理时刻保持原样。

- B（当前默认）：`WALLET_DEFER_DOCK_OPAQUE_ONE_FRAME=true`，`WALLET_DEFER_ADD_OPAQUE_ONE_FRAME=false`，只延后导航栏。
- A：在原 Profile 启动命令后加 `--dart-define=WALLET_DEFER_DOCK_OPAQUE_ONE_FRAME=false`，加号的开关仍保持 `false`。两组只比较导航栏的透明度终点。
- 两组都保持 `WALLET_RETURN_CLEANUP_DELAY_MS=0`、`WALLET_RETAIN_DOCK_TRANSFORM_LAYER=false`、`WALLET_ROUNDED_FLIGHT_CLIP=true`（当前默认）。旧启动命令中的冲突参数需要删除或改为当前值，修改后重新启动应用。原 `WALLET_REVEAL_DOCK_AFTER_CARDS` 顺序开关已撤回。
- 时间线基础标记仍为 `WalletReturn.Begin`、`WalletReturn.PoseSettled`、`WalletReturn.CleanupStateCommit`、`WalletReturn.CleanupFrameBuilt`。返回参数分别记录 `deferDockOpaqueOneFrame` 和 `deferAddOpaqueOneFrame`，并记录 `revealDockAfterCards=false`，确认本次只有导航栏延后。
- B 额外标记 `WalletReturn.OpacityHoldFrame` 和 `WalletReturn.OpacityRestoreFrame`，正常只应出现 `control=dock`，不应出现 `control=add` 的保持/恢复事件。用事件时间关联返回，`transitionId` 配对控件事件，`schedulerFrameUs` 区分两个 UI 帧。这些标记不表示 GPU 已完成绘制。
- 在详情静止时开始录制，返回结束后约半秒停止；关注加号按原时刻恢复的帧与下一帧导航恢复的帧，比较 Raster 编码及提交耗时。延后只用于定位，不把峰值移动当成优化收益。初始静止界面及系统禁用动画时不额外保持一帧。

加号拥有独立的 `WALLET_DEFER_ADD_OPAQUE_ONE_FRAME` 开关，默认关闭；后续若单独测试加号，需同时关闭导航栏的延后开关，避免混合两个变量。
